# USB HID 本机验证与滚轮节奏

跨 USB/BLE 两条输入链路、硬件实验和手机设置的汇总见[电脑串口控制 iPhone：实测方案与实验记录](../../../doc/dev/verified-pc-iphone-control.md)。

2026-11-16，用户决定以本仓库作为后续主要开发项目，原 Windows BLE HID 项目改为参考。现有测试使用 ESP32-S3-WROOM-1 新板，原生 USB 口连接 iPhone，串口连接 PC 的 COM24。COM 编号取决于当前连接，不能作为硬件固定标识。AirPlay 画面仍通过参考项目的现有服务获取；这不是已完成的服务迁移。

## 按钮与坐标

按钮修复使默认绝对鼠标沿用参考项目的报告语义：Report 10 发送绝对 X/Y，Report 11 单独发送按钮，Report 12 承载滚轮。点击为按钮按下后约 60 ms 松开。原上游合并布局在同一 iPhone 的网页对照中未产生完整点击事件，完整布局则通过按钮点击和输入框焦点复测；尚未隔离决定兼容性的单一描述符字段。该板实测 ESP32-S3 revision 0.2、16 MB Flash 和 8 MB PSRAM，具体 PCB 型号尚未确认。

后续在本机测试中，三个屏幕位置的指针落点接近目标；三次普通点击和一次 150 ms 按压分别使测试按钮计数增加一次。700 ms 按压的网页按下到松开约 702 ms，最终被网页识别为点击，不能据此认定长按菜单可用。英文输入 `abc123` 后退格得到 `abc12`。这些结果不代表全屏坐标、所有应用或其他设备均已验证。

## 滚轮与拖动

同一固件上，单条或以约 350 ms 间隔发送的滚轮报告均返回成功，Safari 收到 `wheel` 事件，页面和快捷指令列表却没有可见滚动。测试页内容超过一屏，用户手动滑动及页面按钮均能改变滚动位置，排除了页面不能滚动这一解释。

将相同滚轮报告以约 100 ms 间隔连续发送后，Safari 测试页向上从 `scrollY=500` 移至 `0`，向下从 `0` 移至 `483`；快捷指令列表也能滚动。可复用的结论是发送节奏影响本机效果，并非单凭报告发送成功就能认定滚动生效。此次通过修改工作区 `.runtime/handsy-usb-test/serial_bridge.py` 增加有数量和间隔限制的 `wheel_burst` 完成测试，未刷写新的滚轮固件；普通串口命令仍保留。该诊断桥是本机临时工具，不代表上游正式接口已具备批量滚轮能力。

拖动测试中，网页收到按下、`touchmove` 和松开事件，但页面位置未改变；拖动滚屏仍未解决。原始事件和截图在工作区 `.runtime/handsy-usb-test/`，临时网页探针已关闭。iOS 版本、锁屏状态、其他应用及其他设备尚未覆盖。

### 2026-11-17：区分物件拖动和页面滚动

新增专用网页探针，物件在按住期间按实际指针事件的位置移动。旧固件的可信事件显示按钮保持为 1，物件横坐标从 39 移到约 102 CSS 像素；松开后按钮为 0。页面空白处分别使用默认步长和 2000 的快速步长向上拖动，均收到触摸事件，但 `scrollY` 保持为 0。该结果表明此页面的物件拖动可用，不能推断所有应用的拖动均可用；Safari 按住拖动页面滚动的问题仍未解决，也未确认其根因。

此前固件新增 `scroll_burst V H COUNT`，在板上以 100 ms 间隔发送 1–20 份滚轮报告，保留原单报告 `scroll` 命令。绝对鼠标的水平滚轮不支持，命令会明确拒绝；断连或超时可能只执行部分报告，不应自动重试。下文为之后封装的单参数接口。

仓库中的旧 TCP server 的 `/api/scroll` 也改为发送批量命令，遇到明确的未知命令才回退；网页滚轮按本次实测的方向发送，并限制同时在途的滚轮请求。此处只做了服务端模拟测试；旧 TCP server 与当前 USB 板的端到端连接尚未验证。

在同一测试页刷入新固件后，`scroll_burst 8 0 8` 使 `scrollY` 从 0 到约 632，`scroll_burst -8 0 8` 使其从约 632 回到 6；10 份反向报告曾回到 0。可信滚轮与滚动事件、物件再次从约 102 拖至 39、点击事件，以及非法次数和水平滚动被拒绝均已记录。实际距离受页面及 iOS 影响，不能当作固定的像素位移。固件为本地开发构建，版本字符串沿用 0.2.5，不是上游发行版本；当前板仅更新了应用分区。探针源码与事件位于 `task/usb-hid-drag/lab/`，运行截图和串口记录在工作区 `.runtime/handsy-usb-test/`。仅测了当前 iPhone 和 Safari 测试页，CLI 和 iOS 端到端连接、其他应用与设备尚待验证。

为检验分离报告是否造成拖动不能滚屏，另外临时刷入 `HID_BLE_LAYOUT=0` 合并报告构建，在同一页面上拖仍收到可信 `touchmove` 而 `scrollY` 保持 6；随后盒子点击和拖动命令虽返回 `ok`，却未观察到盒子的按下或移动事件，期间页面持续收到 `touchmove`，松开状态未得到确认。这个对照不支持直接换回合并布局，也不足以确定 iOS 不支持鼠标拖动滚屏的普遍结论。实验结束恢复了分离报告构建。

再以 `ABS_POINTER=0` 的上游标准相对 USB 鼠标作同页对照：在空白处按住上移约 104.5 CSS 像素并释放，可信事件和松开状态正常，但 `scrollY` 保持 632。这个单次对照也没有解决当前页面滚动，不能据此排除其他固件、iOS 设置或应用行为。实验结束已恢复分离报告的正式构建。

### 单参数滚动接口

上层使用 `scroll(amount)`：整数 `-4..4`，正数向下、负数向上、零不动；在当前指针所在的滚动区域生效。单位是大致滚动量，不是屏幕像素或保证的页面比例。固件命令为 `scroll_by AMOUNT`；节奏、报告数量和单次上限由固件负责，使用旧固件时会明确返回未知命令。中途断连或响应超时可能已部分执行，不能自动重放。

已实测调用链是电脑本机临时诊断桥 → COM24 串口 → ESP32 `scroll_by` → USB HID → iPhone。诊断桥位于工作区 `.runtime/handsy-usb-test/serial_bridge.py`，不属于主项目的正式服务；测试时通过本机端口 8896 发送带请求编号的串口命令，例如 `10003 scroll_by 1`。COM 号和进程状态均需以当前连接为准。同一固件的绝对定位和点击也曾沿此串口链路实测。原有 `scroll`、`scroll_burst` 保留。

2026-11-17 用户明确：PC 应通过串口与 ESP32 通信，ESP32 到 iPhone 可分别采用 USB HID 或 BLE HID；暂不修改上游 CLI/MCP。此前对 CLI/MCP 的未提交修改已撤回。iOS Agent 和旧 TCP server 中曾添加滚动接口，但未通过当前串口链路的端到端验证，不能作为 PC 串口服务已完成的证据。旧 BLE 项目的串口协议与本 USB 固件的串口协议不同，不能直接互换；两种模式如何统一到正式 PC 入口尚待确定。

当前 iPhone 的 Safari 测试页上，新固件 `scroll_by 1` 使 `scrollY` 从 0 到约 626，`-1` 返回 0；`2` 到约 797 时触底，`-2` 返回 0，因此该次不能验证距离与数值成比例。超出范围、小数及多余参数被拒绝，`0` 不产生滚动。以上为单设备网页结果，其他应用的距离和可滚动区域需要分别观察。

## 快捷指令回归

使用修复后的滚轮控制，在当前 iPhone 配置了 96 个每日固定时刻，均调用同一个 `PausePlayback` 快捷指令。解锁状态下，19:00 定时触发使静音测试音频在约 1.9 秒后暂停；音频已暂停时再次运行指令，没有重新播放。锁屏触发未测试；快捷指令未实现运行状态检测或互斥，不能保证异常重叠时不重复启动。详见[快捷指令实测](../../../doc/user/iphone-pause-playback.md)。


### 2026-11-17 后续：正式 CLI/MCP 串口入口回归

用户后续明确以本仓库 CLI/MCP 为正式 PC 入口，分支 `feature/serial-usb-control` 已将 PC 蓝牙控制替换为串口，复用当前 USB 固件，未重新烧录。正式 CLI 与 MCP 在本地测试页均完成计数点击和 scroll(+1/-1)，scrollY 0→626→0；150 ms 按压观察到约 143 ms 的 down/up 间隔并释放，swipe 将物件从约 (43,298) 移到 (140,317)，页面 scrollY 保持0。单次 --aim 后点击通过。英文键盘下 abc123、退格至abc12与普通空格输入通过；豆包中文组合态曾出现U+2006，不能将其记为精确ASCII输入通过，测试后已恢复豆包输入法。

本次证明正式入口的有限整合回归，不继承参考 Backend 全部 guard/校准验收。静止投屏可能不产生新帧，CLI 当前五秒门限会拒绝过期截图；本轮测试页用持续时钟生成新画面。可信事件、截图与完整边界见 [正式入口实机回归](../../../task/serial-control/live-validation.md)。
