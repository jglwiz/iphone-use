# 运行与验收

使用此页比较 USB/BLE 输入效果，或验证 CLI/MCP 拒绝输入后没有页面变化。正式控制 API 见 [串口控制](../../../../cli/doc/serial-control.md)。本页不会生成 frame_id/frame_time，不操作串口，也不会自动连接、切路或配对。

## 启动与记录

使用 Python 3.10+ 从仓库根启动 README 中的命令，host 为手机可达的 PC 地址；127.0.0.1 只供离线测试。output 使用新的 `.runtime/hid-acceptance/<run-id>/`，保持在 Git 忽略范围。测试完成以 Ctrl-C 停止本次服务；不结束未知端口占用进程。

打开页面会申请服务器生成的 run_id/page_id；页面显示两者和版本。每次重新加载产生新 page_id，开始新用例时记录实际 ID。证据写入 events.jsonl，记录含服务端接收时间。GET /events 导出本次日志，GET /status?page_id=... 查看当前在线性和最后状态。页面标签和 isTrusted 都不能证明 HID 实际通路，必须结合 CLI device info 及 USB/BLE 计数。

事件序号从1递增，服务端追加并 fsync 后才确认。客户端最多缓存512个事件，失败后重传同一事件；服务端对相同内容去重，不重复落盘。不同内容复用序号或缺号均标记证据异常；队列溢出、磁盘错误要换新页面/运行，不能接着宣称完整。任何重传均是观测日志，不是 HID 命令。

每秒后台心跳记录完整文本、点击数、滚动位置和元素矩形；网络故障时页面显示“证据不足”。服务端超过4秒没有事件/心跳时标记离线或过期。`evidence=current` 只表示当前没有已知问题，不是完整历史窗口的通过判据。

负向用例必须取开始及结束的已落盘状态，核对窗口内 page_id 不变、事件序号连续、pending/lost=0、无 gap/conflict/storage 错误且心跳间隔正常。后台标签页被节流、页面换页、事件缺号或心跳空档均记“证据不足”，不能用没有日志证明拒绝或无重放。保留异常和恢复前后的日志，不自动清空。

## 动作与静止模式

动作模式每500ms刷新可见时钟，供 AirPlay 产生新帧。静止模式停止时钟、隐藏文本光标并移开焦点；健康后台心跳与落盘确认不会更新可见页面。模式切换本身仍会产生事件；等待这些事件落盘、页面稳定后再开始静止观察窗口。网络异常仍会改变警告文字，该变化不能作为正常静止验收。

静止至少8秒后使用正式 CLI/MCP 截图，检查原 frame_time/id、observation_only 和 after_action=false。页面心跳只证明页面在运行，不证明投屏连接；以画面服务明确报告的连接状态为准。遇到来源不报告断开时保留 unknown，不按帧年龄推断。

## 实机执行

PC→ESP32 保持独立串口和供电，只有一个 daemon 拥有串口。使用现有 AirPlay 服务，不重启。先确认页面的当前截图、输入法和设备状态，再发一次明确动作；客户端成功回执不能替代页面效果。

切路使用正式流程：停止自己的 daemon → 设置 ESP32AGENT_HID_OUTPUT=usb/ble → 重新运行 device info。BLE 必须连接、加密且全部报告订阅；USB 就绪不能代替 BLE 就绪。USB 可用于操作手机设置完成目标设备配对，不能删除其他设备。

记录每项的 run/page/case ID、CLI/MCP入口、真实输出、动作前后设备状态与报告计数、命令与回执、窗口时间、DOM日志及原始截图元数据。结果用通过/失败/未运行/证据不足，不按“总测试数”代替覆盖。

| 用例 | 必须观察的效果 |
|---|---|
| 多点及返回同点 | 指针或目标命中符合截图所选点；CSS矩形只是辅助，不能直接当作截图像素 |
| 单击/重复点击 | 每个新命令对应正确点击增量，最终buttons=0 |
| 键盘 | 已确认英文输入法下ASCII、Shift、空格、退格；BLE超过16字符完整输入 |
| 正负与零滚轮 | scrollY方向正确；零不动，不要求固定像素或往返恰好抵消 |
| 有界按压 | 同一页面monotonic_ms的down/up间隔及最终释放，允许传输延迟 |
| 拖动 | box矩形位置变化、pointerup/cancel及buttons=0；不等同页面滚屏 |
| 静止帧 | 页面稳定超过5秒，截图保留来源真实时间，不假装操作后新帧 |
| BLE断连拒绝 | USB仍可用时选BLE，CLI/MCP输入被拒绝，完整观察窗口内无效果、USB计数不增加 |
| 重连恢复 | 明确用USB恢复目标配对；静置无迟到动作；新发命令各产生一次效果 |
| 手机端USB拔线 | 用户确认实际拔线、PC串口保留，纯BLE定位/点击/键盘可用；usb=asleep不代表物理插线 |

基本输入按 USB/BLE × CLI/MCP 分项记录，不能互相代替。负向测试需要执行前已断连；动作中途断链、旋转、锁屏和长期稳定性另列未来用例。为纯 BLE 项实际拔插线需要用户完成物理操作，软件不能模拟；在此条件未满足时保留未运行，不删除待替代的旧测试。

结束恢复原输入法和约定输出，确认held=0，停止本次测试页服务。不要停止用户的投屏服务。原始日志和截图留本地，长期结论维护在本模块文档中。
